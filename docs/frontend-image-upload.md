# Frontend Handoff: 사용자 이미지 업로드

이 문서는 프론트엔드 팀에 전달하기 위한 사용자 이미지 업로드 연동 가이드입니다.

## 목적

사용자가 프로필 이미지나 일반 사용자 이미지를 업로드하면:

1. 이미지 업로드 서비스가 원본 이미지를 저장합니다.
2. 필요하면 작은 썸네일도 함께 생성합니다.
3. 업로드 응답으로 이미지 식별값과 공개 URL 정보를 돌려줍니다.
4. 프론트 또는 메인 백엔드는 그 응답을 사용자 프로필 데이터와 연결해 저장합니다.

## 가장 중요한 주의사항

현재 업로드 서비스는 `X-API-Key` 또는 `Authorization: Bearer ...` 기반입니다.

즉:
- 브라우저 프론트엔드에서 이 API를 직접 호출하면 안 됩니다.
- 정적인 API 키를 웹 브라우저에 넣으면 누구나 키를 볼 수 있습니다.

현재 기준 권장 구조:

1. 브라우저 프론트엔드는 메인 백엔드로 파일을 보냅니다.
2. 메인 백엔드는 서버 간 통신으로 이미지 업로드 서비스에 파일을 전달합니다.
3. 메인 백엔드는 업로드 응답을 받아 사용자 프로필에 연결합니다.
4. 프론트엔드는 최종 사용자 프로필 정보 또는 이미지 URL만 받습니다.

즉, "프론트가 직접 image.gorani.me/upload를 호출하는 구조"는 현재 권장하지 않습니다.

## 권장 연동 구조

프론트 관점 흐름은 아래처럼 생각하면 됩니다.

1. 사용자가 이미지 파일을 선택합니다.
2. 프론트는 이미지 미리보기를 보여줍니다.
3. 프론트는 메인 서비스 백엔드의 사용자 이미지 업로드 API를 호출합니다.
4. 메인 백엔드는 내부적으로 이미지 업로드 서비스 `POST /upload`를 호출합니다.
5. 메인 백엔드는 응답에서 `sha256`, `original.url`, `variants`를 받아 사용자 레코드에 저장합니다.
6. 프론트는 최종적으로 사용자 프로필 응답 안의 이미지 URL을 사용합니다.

## 업로드 서비스 API 요약

현재 이미지 업로드 서비스는 아래 API를 제공합니다.

### 업로드

- Method: `POST`
- Path: `/upload`
- Content-Type: `multipart/form-data`
- File field name: `image`
- Auth: `X-API-Key` 또는 `Authorization: Bearer ...`

예시 요청:

```bash
curl -X POST \
  -H "X-API-Key: <server-side-secret>" \
  -F "image=@/path/to/photo.png" \
  http://127.0.0.1:8080/upload
```

예시 응답:

```json
{
  "id": 1,
  "sha256": "43b78bfe96a88f7f2b500ee07b389d9838d8c10b698d96223513b865415b967a",
  "original": {
    "url": "/i/original/43/b7/43b78bfe96a88f7f2b500ee07b389d9838d8c10b698d96223513b865415b967a.png",
    "content_type": "image/png",
    "width": 400,
    "height": 400,
    "bytes": 4889
  },
  "variants": [
    {
      "kind": "thumb_160",
      "url": "/i/variants/43/b7/43b78bfe96a88f7f2b500ee07b389d9838d8c10b698d96223513b865415b967a__thumb_160.webp",
      "width": 160,
      "height": 160,
      "bytes": 5364
    },
    {
      "kind": "thumb_320",
      "url": "/i/variants/43/b7/43b78bfe96a88f7f2b500ee07b389d9838d8c10b698d96223513b865415b967a__thumb_320.webp",
      "width": 320,
      "height": 320,
      "bytes": 6344
    }
  ]
}
```

주의:
- `variants`는 비어 있을 수 있습니다.
- 파일 확장자나 썸네일 포맷은 서버 설정에 따라 바뀔 수 있습니다.
- 현재 응답의 `url`은 `/i/...` 형태의 공개 경로이며 완전한 절대 URL이 아닙니다.
- 메인 백엔드는 공개 경로 앞에 이미지 딜리버리 주소 `https://image.gorani.me`를 붙여 프론트에 절대 URL로 반환하는 것을 권장합니다.
- 프론트가 해시, 확장자, 썸네일 파일명을 조합하면 안 됩니다. 업로드 응답의 경로 또는 메인 백엔드가 완성한 절대 URL을 사용해야 합니다.

예시:

```text
업로드 응답 경로: /i/original/43/b7/<sha256>.png
프론트 사용 URL: https://image.gorani.me/i/original/43/b7/<sha256>.png
```

### 메타데이터 조회

- Method: `GET`
- Path: `/assets/<sha256>`

이 API는 주로 운영/디버깅용입니다. 일반적인 사용자 프로필 표시에서는 메인 백엔드가 저장한 URL을 그대로 쓰는 것이 더 단순합니다.

### 삭제

- Method: `DELETE`
- Path: `/assets/<sha256>`
- Auth: 필요

사용자 이미지 교체 시 이전 이미지 정리가 필요하면 메인 백엔드에서 이 API를 호출할 수 있습니다.

## 프론트가 저장해야 하는 값

프론트나 메인 백엔드가 최종적으로 보관해야 하는 값은 아래 중 하나입니다.

최소 저장 권장:
- `sha256`
- `original.url`
- 필요한 경우 대표 썸네일 URL 하나

실무 추천:
- `sha256`
- `original.url`
- `original.width`
- `original.height`
- `variants` 배열 전체 또는 대표 썸네일 URL

왜 `sha256`를 같이 저장하냐면:
- 이후 삭제 API 호출에 쓸 수 있고
- 중복 업로드나 재처리 시 식별자로 쓰기 쉽기 때문입니다.

## 프론트 표시 규칙 권장안

사용자 프로필 이미지처럼 작은 영역에서 보여줄 경우:

- 목록/작은 아바타: `thumb_160` 우선 사용
- 프로필 상세/중간 크기: `thumb_320` 우선 사용
- 원본 상세보기: `original.url` 사용

단, 실제 사용할 URL은 `kind`를 보고 응답에서 찾아야 합니다.

예시:

- `thumb_160`가 있으면 아바타 용도로 사용
- 없으면 `thumb_320`
- 그것도 없으면 `original.url`

## 프론트 UX 권장 사항

- 업로드 전 이미지 미리보기 제공
- 업로드 중 로딩 상태 표시
- 업로드 버튼 중복 클릭 방지
- 실패 시 에러 메시지 표시
- 업로드 성공 후 즉시 새 이미지 반영
- 이미지 교체 시 이전 이미지가 보이더라도 캐시 때문에 잠깐 남을 수 있음을 감안

## 프론트 입력 제한 권장 사항

서버에서도 검사하지만 프론트에서 미리 막아주면 UX가 좋아집니다.

권장 체크:
- 이미지 파일만 선택 가능하게 제한
- 너무 큰 파일은 업로드 전 경고
- 확장자만 믿지 말고 브라우저가 제공하는 MIME 정보도 함께 확인

현재 서버 기본 최대 업로드 크기 예시는 `20MB`입니다.

## 에러 처리 가이드

프론트 또는 메인 백엔드에서 아래 상태 코드를 예상하면 됩니다.

- `201 Created`
  업로드 성공
- `400 Bad Request`
  잘못된 요청, 이미지 아님, 필드 누락 등
- `401 Unauthorized`
  인증 실패
- `404 Not Found`
  삭제 또는 조회 대상 없음
- `411 Length Required`
  업로드 요청에 `Content-Length`가 없음. 일반적인 브라우저/HTTP 클라이언트는 자동으로 설정함
- `413 Content Too Large`
  요청 본문이 서버의 최대 업로드 허용 크기를 초과함
- `500`
  서버 내부 오류

프론트 표시 예시:

- `400`: "올바른 이미지 파일을 선택해주세요."
- `401`: "업로드 권한이 없습니다."
- `411`: "업로드 요청을 처리할 수 없습니다. 앱을 업데이트한 뒤 다시 시도해주세요."
- `413`: "이미지 파일이 너무 큽니다. 더 작은 이미지를 선택해주세요."
- `500`: "이미지 업로드 중 오류가 발생했습니다. 잠시 후 다시 시도해주세요."

## 프론트가 직접 브라우저에서 업로드해야 한다면

현재 구조로는 정적 API 키를 브라우저에 넣으면 안 됩니다.

브라우저 직접 업로드가 꼭 필요하다면 추가 작업이 필요합니다.

필요한 방향 예시:
- 짧은 수명의 업로드 토큰 발급
- 1회용 업로드 세션
- presigned URL 방식

이 기능은 현재 구현 범위에 없습니다.

## 프론트 팀에 전달할 핵심 문장

아래 문장만 전달해도 큰 틀은 충분합니다.

"사용자 이미지는 프론트가 직접 이미지 업로드 서버를 호출하지 않고, 메인 백엔드를 통해 업로드해야 합니다. 업로드 성공 시 응답으로 받은 `sha256`, `original.url`, `variants` 중 필요한 값을 사용자 프로필 데이터에 저장해서 사용하면 됩니다. 메인 백엔드는 `/i/...` 공개 경로를 `https://image.gorani.me/i/...` 절대 URL로 바꿔 프론트에 전달하고, 프론트는 해시나 파일명을 직접 조합하지 않아야 합니다."
